📘 Guida a postAllIn

Benvenuto nella documentazione di postAllIn. Questo strumento (attualmente in fase di testing) automatizza la creazione del file allin.csv utilizzato per la gestione dei tornei di scacchi in Italia[cite: 3].

📂 1. Cos'è cosa (I File Principali)

Il progetto "postallin-main.zip" si divide in due applicazioni web distinte ma complementari, che girano interamente all'interno del browser locale:

1. index.html (Generatore postAllIn)

Cos'è: È il cuore del progetto[cite: 3].

Cosa fa: Prende i database separati (FSI, Vega, FIDE), li incrocia e genera il file allin.csv finale pronto per l'uso[cite: 3]. È la dashboard principale che l'arbitro o l'organizzatore utilizzerà maggiormente[cite: 3].

2. candidati.html (Trova Candidati FIDE)

Cos'è: È uno strumento di supporto opzionale[cite: 3].

Cosa fa: Serve a trovare potenziali abbinamenti tra giocatori italiani (ID FSI) che non hanno ancora un ID internazionale e il database mondiale FIDE[cite: 2]. Confronta i giocatori usando Nome + Anno di nascita per suggerire associazioni[cite: 2].

⚙️ 2. Cosa fa cosa (Il Flusso di Lavoro)

Entrambi gli script lavorano "a strati", arricchendo progressivamente i dati dei giocatori. Ecco come funzionano le due procedure.

Flusso A: Trovare nuovi ID FIDE (tramite candidati.html)

Se l'organizzatore vuole cercare ID internazionali mancanti, usa questo modulo[cite: 2]:

  • Step 1 & 2 (Filtro base): Legge l'elenco tesserati FSI e il file Vega. Isola tutti i giocatori italiani che non hanno un ID FIDE già registrato in Vega[cite: 2].
  • Step 3 (Ricerca FIDE): Legge il massiccio file players_list.txt della FIDE. Poiché il file è enorme, usa una tecnica chiamata streaming (legge il file a piccoli pezzi per non bloccare il browser)[cite: 2]. Cerca corrispondenze esatte tra nome e anno di nascita[cite: 2].
  • Step 4 (Risultato): Scarta i candidati il cui ID FIDE è già assegnato a qualcun altro e segnala le omonimie. Genera un file candidati.csv con i suggerimenti[cite: 2].

Flusso B: Generare il File allin.csv (tramite index.html)

Questo è il processo di assemblaggio finale[cite: 3]:

  • Step 1 (Dati Anagrafici): Legge elenco_tesserati.csv per creare la base. Estrae nome, ID FSI, sesso, data di nascita, regione, provincia e società[cite: 3].
  • Step 2 (Dati Italia): Sovrascrive o aggiunge dati leggendo aaaa_mm_vega.csv, aggiornando Elo Italia, Categoria e K Italia[cite: 3].
  • Step 3 (Integrazione Candidati - Opzionale): Se viene caricato il file candidati.csv generato in precedenza, assegna i nuovi ID FIDE trovati, aggiungendo l'etichetta "(presunto)" accanto al nome del giocatore per segnalare all'arbitro che il dato non è ancora ufficiale in Vega[cite: 3].
  • Step 4 (Dati Internazionali): Legge il file players_list.txt (sempre tramite streaming) per estrarre Elo Standard/Rapid/Blitz, K factor FIDE e titoli mondiali (GM, IM, ecc.)[cite: 3]. Confronta anche il sesso e l'anno di nascita FSI con quelli FIDE, segnalando eventuali discordanze nel Log[cite: 3].
  • Output Finale: Genera il file allin.csv formattato correttamente con punto e virgola come separatore e offre un Log dettagliato da scaricare in caso di errori[cite: 3].
